# Decisions

2026-10-12 의논으로 확정. 여기 있는 것은 재논의하지 않고, 바꿀 때는 이 문서를 고치고 이유를 남긴다.

| # | 결정 | 선택 | 이유 |
|---|---|---|---|
| D1 | 저장소 | `~/Project/horang-universe`, GitHub `zaehorang/horang-universe` 공개 | SKALA 는 비공개 학습 기록이 섞여 Pages 를 켤 수 없다 |
| D2 | 세계관 비유 | 지리 계열 지역(해안·항만·구역) | 기존 세계(우편 도시·항구·공항·도서관)와 자연스럽게 어울린다. 캠퍼스 비유는 건물 안에 항구가 있는 크기 불일치로 기각 |
| D3 | 엔진 배치 | `tooling/engine/` 하나를 전 세계가 참조. 복사 없음 | 세계마다 복사하면 버전이 어긋난다(http-https 가 한 버전 뒤처진 사례) |
| D4 | 엔진 버전 | 버전 폴더 없음. 변경 시 전 세계 검사 + CHANGELOG | 단순하고 모든 세계가 늘 최신. 안전망은 검사가 맡는다 |
| D5 | 디자인 자유 | 엔진 style.css 를 CSS 변수로 열고, 읽는 법은 고정 | 세계별 분위기는 열어 주되 탐험 방식은 어디서나 같아야 한다 |
| D6 | 허브 | 평면 SVG 가 아닌 엔진 기반 "세계들의 세계" | 시각 일관성, 대륙 간 사건을 같은 장면 기능으로 재생 가능 |
| D7 | 등록부 읽기 | 허브는 `atlas.json` fetch, 세계 페이지는 생성된 `atlas.js` 스크립트(선택). 로컬은 http.server | 세계 페이지는 fetch 대기 없이 동기 로드한다. 두 파일은 같은 `build_atlas` 실행에서 만들고 함께 stale 검사해 어긋남을 막는다 |
| D8 | 메타데이터 주인 | 세계 것은 content.js `meta`, 세계관 것은 `worlds.json`, 색인은 생성물 | 두 곳을 손으로 맞추는 어긋남을 구조로 막는다 |
| D9 | 공용 값 | `shared/values.js` JS 상수, 여러 벌 | 값이 한 곳에서 바뀐다. 벌을 여러 개 두어 세계 간 겹침을 피한다 |
| D10 | 세계 경로 | `worlds/<id>/` 평평 | 지역 재편 시 URL 불변 |
| D11 | 문 | 한쪽에만 적고 양방향 해석 | 중복 기술 없음 |
| D12 | 배포 | Actions 검사 통과 후 Pages | 깨진 상태가 공개되지 않는다 |
| D13 | 검색 입구 | 허브 지도 상단 검색칸 + 자유 클릭 탐색 | 입구 하나, 이동 자유 |
| D14 | 스킬 분리 | 세계 제작은 원본 explorable-world(수정 금지), 세계관 운영은 로컬 `universe` | 범용 스킬은 다른 프로젝트에서도 써야 한다. 역반영은 별도 요청 시 |
| D15 | 외부 라이브러리 | GSAP · Pretendard · JetBrains Mono 를 `tooling/vendor/` 에 배포 | 공개 사이트가 CDN 하나에 묶이지 않게. 독립 세계는 CDN 유지 |
| D16 | 사건 ID | events 에 안정 `id`, 앵커 `#ev=<id>&b=<n>` | 사건 끼워 넣어도 문·검색 링크 유지 |
| D17 | 상태 | draft → verified → archived 한 방향 | archived 는 허브 숨김 + 리다이렉트. 리다이렉트 파일 내용은 수동 확인 |
| D18 | 허브 좌표 | `new_world` 가 초기 좌표를 제안하고 운영자가 관리, 동일 좌표 중복 검사 | 세계 20개 전엔 전체 자동 배치가 과하다 |
| D19 | Git | main 직접 push, PR 없음, Actions 는 main push 에만 | 1인 작업 |
| D20 | 테스트 | 정적 검사(Actions) · verify_browser(로컬 필수) · 스크린샷 수동 비교 | 자동 시각 회귀는 넣지 않는다 |
| D21 | 구형 세계 | k8s-cluster-architecture 는 들여오지 않고 항구의 "만약에" 사건으로 흡수 후 archived | GSAP·ISO 를 안 쓰는 다른 구조라 이관은 재작성과 같다 |
| D22 | 도메인 통일 | `my-shop.example.com` 대표. network-layers 만 `my-shop.example` 예외 | 그 세계의 바이트 수(78·130·144)가 도메인 길이에 묶여 있다 |
| D23 | 도서관 인물 | mina·joon, my-pay 유지. "결제 서비스 벌"로 등록 | 대륙 간 사건에서 주문 가게가 결제를 부탁하는 관계로 쓴다 |
| D24 | 데스크톱 전용 | 모바일 미대응 | 기존 세계가 전부 데스크톱 전제 |
| D25 | 진도 연결 | 넣지 않음 | SKALA Knowledge · learning-state 와 섣불리 묶으면 저장 영역 규칙과 충돌 |
| D26 | 디자인 방향 | 「탐험가의 지도책」: 지도(SVG)는 세계 소유의 블록 디오라마, 읽기 장치(패널·자막·허브 바다·검색칸)는 잉크 `#1d2b3a`·종이 `#fbfaf7`·나침반 파랑 `#2563eb`·바다 `#5fb0c8` 넷으로 고정. 세계가 바꾸는 변수는 `--world-bg` `--world-bg-deep` `--world-ground` `--world-texture` `--acc`(파랑 계열 안) 다섯뿐. 이름 색 셋은 값까지 고정 | 2026-10-12 디자인 자문. 기존 다섯 세계의 잉크·파랑·블록 톤을 자산으로 보고 "종이"만 더해 묶는다. 상세는 `design.md` |
| D27 | 이관 세계의 사건 유형 | `events[].kind` 가 세 종류 미만이면 `verified` 세계에서도 경고로 기록하고, Phase 2 검사를 막지 않는다 | 이관 속도 우선, 유형 빈칸은 2-8 에서 측정. 보강은 Phase 4 |
