# 층층 우체국 빌딩 — 작업 노트

네트워크 계층(OSI 7계층 · TCP/IP 4계층)을 탐험하는 지도다. 컴퓨터마다 7층 빌딩이 있고, 편지(HTTP 요청)가 층을 내려가며 봉투를 겹겹이 쓰고, 도로·스위치·라우터를 지나, 맞은편 빌딩에서 아래층부터 한 겹씩 벗겨진다.

## 여는 법

```bash
cd /Users/zaehorang/Project/horang-universe
python3 -m http.server 8000   # → http://127.0.0.1:8000/worlds/network-layers/
```

데스크톱 브라우저 전용이다. GSAP·폰트는 저장소의 `tooling/vendor/` 를 참조한다.

## 파일

| 파일 | 내용 |
|---|---|
| `world.js` | 지도 그리기 · 배경 움직임 · 기준 상태(reset) · 사건별 장면, 층 안의 방(`ROOMS`) |
| `content.js` | 부품별 3겹 설명 · 사건별 자막과 실제로는? · 이름 색 규칙 |
| `world.css` | 이 세계 전용 스타일 (봉투 · 방 · 메시지 카드 · 하늘→풀 바탕 · 점 질감) |
| `index.html` | `tooling/templates/world-index.html` 복사본. 공용 엔진은 `../../tooling/engine/`, 라이브러리·폰트는 `../../tooling/vendor/` 를 참조한다. 세계 폴더에 엔진 복사본을 두지 않는다 |

## 지금 있는 것

- **웹 페이지 요청 한 번** (9장면): 7층 HTTP → 6·5층 통과 → 4층 TCP 봉투 → 3층 IP 봉투 → 2층 Ethernet 겉봉투(받는 쪽은 라우터 MAC) → 1층 신호 → 스위치(MAC만 읽음) → 라우터(겉봉투 교체 · TTL −1) → 서버에서 아래층부터 벗기기.
- **빌딩 안 둘러보기** (6장면): 7층부터 1층까지 층 앞으로 다가가면 그 층의 방이 펼쳐지고, 다음 장면에서 접히며 나온다. 방마다 그 층에서 알아야 할 것을 물건과 이름표로 보여 준다.
- **TCP 연결 맺기** (4장면): SYN → SYN-ACK → ACK, 양쪽 4층의 상태 표(`CLOSED`/`LISTEN` → `SYN-SENT`/`SYN-RECEIVED` → `ESTABLISHED`), 마지막에 "연결 = 양쪽 4층의 기록"을 점선으로.
- **옆 장비 MAC 찾기** (5장면): ARP 표가 빈 노트북 → 동네 전체 방송(`ff:ff:ff:ff:ff:ff`) → 스위치가 모든 출구로 복사하고 MAC을 배움 · 옆자리 PC는 버림 → 라우터만 응답 → ARP 표에 기록.
- **HTTPS로 봉인하기** (6장면): ClientHello → ServerHello + 인증서(이미 암호화) → 인증서 확인 · 양쪽 자물쇠 → 편지를 6·5층에서 봉인 → 길 위에서 보이는 것(주소 · 포트 · SNI)과 안 보이는 것 → 서버가 봉인을 풀어 nginx에게.
- 누를 수 있는 부품 10개: 층 6개(7 · 6·5 · 4 · 3 · 2 · 1), 스위치, 라우터, curl, nginx. 옆자리 PC(`10.0.1.31`)는 ARP 사건용 소품이라 누를 수 없다.

### 예시 값 (모든 블록에서 같게 쓴다)

| 대상 | 값 |
|---|---|
| 노트북 | `10.0.1.23` (DHCP) · MAC `00:00:5e:00:53:23` · 임시 포트 `51514` |
| 라우터 | `eth0 10.0.1.1` (`…53:01`) · `eth1 10.0.2.1` (`…53:02`) |
| 서버 | `10.0.2.10` (고정) · MAC `…53:10` · nginx 포트 80 |
| 길이 | HTTP 78 · TCP 헤더 32 (옵션 12 포함) · IP 헤더 20 · IP 길이 130 · Ethernet 헤더 14 · 프레임 144 (+FCS 4) |
| TTL | 노트북 64 → 라우터 지난 뒤 63 |
| TCP 연결 | 노트북 ISN `3172449120` · 서버 ISN `2841067534` · 타임스탬프는 요청 사건의 GET(`TS val 3051624811 ecr 1923044210`)과 이어진다 |
| ARP | `10:20:59` 에 요청·응답 — 요청 사건(`10:21:07`)보다 앞이고, 둘러보기 2층 방의 tcpdump 와 같은 줄 |
| HTTPS | 별도 연결 · 임시 포트 `51522` · 포트 443 · 인증기관은 가짜 이름 `Example CA` |

MAC은 문서용 대역 `00:00:5e:00:53:xx`, 도메인은 `my-shop.example` 이다.

`meta.values` 는 `shop-web` 이며 가게 이름은 `shared/values.js` 의 `shortName` 을 참조한다. 도메인은 바이트 수 보존을 위한 D22 예외로 유지하고(번들의 `domain`·`publicIp` 는 일부러 쓰지 않는다), `content.js` 가 예제 요청이 78바이트인지 단언해 어긋나면 콘솔 오류를 낸다. 허브 지붕색 `meta.hubColor` 는 우체국 지붕 `ISO.C.roofR` 윗면 `#e07a5f` 이다. 내부망 주소·MAC·포트·바이트 수는 세계 고유 값으로 둔다. 문은 `http-https:shop` 쪽에서 선언하므로 이 세계의 `meta.doors` 는 빈 배열이다. 사건 유형은 정상 흐름(`normal`)과 둘러보기(`tour`) 두 종류이며, 셋 미만 보강은 D27에 따라 후속 단계에서 다룬다.

### 일부러 단순화한 것

- 회사 안 두 동네를 라우터 하나가 잇는다. 집 공유기의 NAT가 끼면 "IP는 끝까지 그대로"가 틀린 말이 되기 때문에 NAT를 뺐다(라우터 패널에 적어 둠).
- 요청 사건은 DNS 조회 · TCP 연결 · ARP가 이미 끝난 상태에서 시작한다(첫 자막에 적어 둠).
- 유선 Ethernet만 그렸다. Wi-Fi는 1층 방과 1층 패널에서 말로만 다룬다.
- 요청 사건은 `http://` 다. HTTPS는 별도 사건에서 443번 연결로 다룬다.
- 연결 맺기 · HTTPS 사건의 메시지는 4층끼리 · 6·5층끼리 바로 나는 것처럼 그렸다. 실제로는 매번 아래층 · 스위치 · 라우터를 거친다(첫 자막에 적어 둠).
- HTTPS 사건은 HTTP/1.1로 가정했다(nginx 설정에 따라 HTTP/2가 협상될 수 있음).

## 검증 상태 (2026-10-12, 사건 5개 기준)

- 정적 검사(`check_world.mjs`): 통과. 경고 2개는 둘 다 의도된 것이다.
  - `world.js 계산된 actor 키 act 호출 2곳` — 층을 `act(..., FLOOR_ACT[i])` 처럼 계산된 키로 만들어 검사기가 문자열 리터럴로 근사 검사한다.
  - `client` 가 어느 장면의 주인공도 아님 — 의도한 것. 옥상의 curl은 소품이고 첫 자막에서 이름만 부른다.
- 브라우저 자동 검사(rubric B, 헤드리스 Chrome): 1512x772 · 1120x700(iframe) 두 크기 모두 통과. 가장 작은 라벨 16.7px / 12.5px. 콘솔 에러 0. 전 사건 30장면 재생 확인.
  - 경고 `request#8`: 말풍선 꼬리가 주인공 근처가 아니라고 1512 폭에서만 나온다. 꼬리는 화면에서 nginx를 가리킨다.
  - 경고 `arp#3`: 옆자리 PC의 "나 아님 → 버림" 말풍선 — 주인공(스위치)이 아니라 옆자리 PC가 말하는 의도된 말풍선.
- 전체 보기 배치: 1512x828 · 1512x772 · 1280x720 · 1120x700 에서 라벨이 사건 패널 · 제목 · 오른쪽 위 버튼과 겹치지 않음. **1000x680 처럼 1.6:1 보다 덜 긴 창에서는 오른쪽 TCP/IP 4계층 라벨이 화면 밖으로 잘린다.**
- 눈으로 본 것: 다섯 사건의 장면 끝 상태 스크린샷(요청 9 · 둘러보기 6 · 연결 맺기 4 · ARP 5 · HTTPS 6장면 전부). 자동화 탭에서 확인해 실제 속도의 매끄러움은 일부만 봤다.
- 실제로는? 의 명령 출력은 각 도구의 실제 형식에 맞춰 쓴 예시다. 실제 장비에서 찍은 캡처가 아니다.

## 추후 고려할 것

### B안 — 층을 눌러 바로 들어가기

지금 둘러보기는 사건(A안)이라 장면 순서대로만 들어간다(장면 점으로 건너뛰기는 된다). 아무 층이나 눌러서 들어갔다 나오려면 공용 엔진에 동작을 새로 넣어야 한다.

- 엔진이 할 일: 부품을 누르면 패널을 여는 대신(또는 패널 안 버튼으로) `WORLD.enter(actorId)` · `WORLD.exit()` 같은 세계 훅을 부르고, 들어가 있는 동안 '나가기' 버튼과 Esc를 둔다.
- 이 지도가 할 일: 이미 있는 `ROOMS` · `room()` · `tourBeat()` 의 펼치기/접기 코드를 훅으로 옮기면 된다. 방 그림은 그대로 쓴다.
- 주의: 엔진은 다른 지도(`http-https`, `eks-security` 등)와 공유한다. 훅이 없는 세계에서는 지금처럼 패널만 열리게 하고, 고친 뒤 각 지도에서 rubric B를 다시 잰다.

### 다음 사건 후보

| 사건 | 보여 줄 것 | 비고 |
|---|---|---|
| 응답 돌아오기 | 200 OK가 같은 길을 거꾸로, 라우터에서 MAC이 반대로 바뀜 | 요청 사건의 거울 |
| 편지를 잃어버리면 | 패킷 손실 → ack 없음 → 재전송, 창 크기 줄이기(혼잡 제어) | 4층 방의 재전송 선반 · 창 크기와 연결 |
| 너무 큰 편지 | MTU 1500을 넘는 데이터 → TCP가 여러 세그먼트로 나눔 | 1층 방의 `mtu 1500` 과 연결 |
| 길 묻기 (traceroute) | TTL 1, 2 … 로 보내고 라우터가 ICMP로 답하기 | 3층 방의 traceroute 출력과 값을 맞춘다 |
| DNS 묻기 (UDP) | 이름 → IP를 UDP 53으로 묻기, TCP와 비교 | 4층 방의 UDP 창구와 연결 |
| 연결 끊기 | FIN · ACK, `TIME-WAIT` | 연결 맺기 사건의 짝 |

사건이 남기는 상태(연결 · ARP 표 · 캐시)가 있으면 다음 사건 첫 자막에 시작 상태를 쓴다.

**사건 패널 크기 주의**: 사건 5개 이상이면 공용 엔진의 두 열 배치를 사용한다. 라벨 크기도 공용 엔진 기본값을 사용하며 세계 CSS에서 덮어쓰지 않는다. `home` 카메라(`y:445`), 옥상 라벨 두 개와 "1번 동네" 라벨 위치는 유지했다. 사건을 7개 이상으로 늘리면 패널이 다시 높아지므로 위 네 크기에서 겹침을 다시 잰다.

### 그 밖에

- 서버 빌딩의 방: 지금은 노트북 빌딩만 들어간다. 서버 쪽 4층(LISTEN 중인 80번 우편함, accept)처럼 받는 쪽 관점의 방도 가능하다.
- 스위치 · 라우터 내부: 장비도 "1·2층만 있는 건물", "1·2·3층만 있는 건물"로 들어가 보면 '장비마다 몇 층까지 여는가'가 더 분명해진다.
- 층 강조 색: 둘러보기의 노란 강조는 같은 층의 오른쪽 빌딩에는 켜지지 않는다. 짝(peer) 개념을 강조하려면 양쪽을 같이 켠다.
- 마지막 장면 말풍선 꼬리(B9 경고)를 nginx 머리 쪽으로 더 붙이기.
